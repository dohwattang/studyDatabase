집계 심화 ROLLUP·HAVING

블록 1/2

소계와 총계 — WITH ROLLUP

1.WITH ROLLUP
2.HAVING

집계에 소계·총계를 더하고, 집계 결과를 다시 필터링한다. 경영 리포트에서 "합계 행"과 "기준 미달 제외"가 바로 이것이다.

WITH ROLLUP — 총계 행 추가

GROUP BY 맨 끝에 붙이면, 맨 아래에 전체 합계 행이 자동으로 생긴다. 카테고리별 아이템 수와 가격 합계를 구해 보자.

MySQL · query.sql
SELECT category,
       COUNT(*) AS 아이템수,
       SUM(price) AS 가격합
FROM item
GROUP BY category WITH ROLLUP;

방어구119900
소비21800

NULL8194200
📌 총계 행의 NULL

ROLLUP이 만든 총계 행은 카테고리 자리가 NULL로 나온다. IFNULL(category, '★총계')로 보기 좋게 바꿔주면 완성도가 높아진다.

실전 — 라벨까지 붙인 총계

MySQL · query.sql
SELECT IFNULL(category, '★총계') AS 카테고리,
       COUNT(*) AS 아이템수,
       SUM(price) AS 가격합
FROM item
GROUP BY category WITH ROLLUP;

같은 방식을 user 테이블에 적용하면 서버별 현황과 전체 평균이 한 번에 나온다. 총계 행의 평균레벨은 8명 전체의 평균이다.

⚠️ ROLLUP과 ORDER BY

ROLLUP 결과에 ORDER BY를 걸면 총계 행(NULL)이 맨 위로 올라오는 등 위치가 달라진다. 이 과정에서는 ROLLUP을 쓸 때 ORDER BY를 붙이지 않는다.

블록 2/2

집계 결과 필터링 — HAVING

1.WITH ROLLUP
2.HAVING

WHERE는 그룹으로 묶기 전에 거른다. 그런데 "합계가 5만원 넘는 카테고리만"처럼 집계 결과로 걸러야 할 때가 있다. 그게 HAVING이다.

WHERE vs HAVING

구분거르는 시점집계함수 사용
WHERE그룹화 전(개별 행)불가
HAVING그룹화 후(집계 결과)가능
MySQL · query.sql
SELECT 컬럼, 집계함수
FROM 테이블
WHERE 개별행조건        -- 1) 먼저 행 필터
GROUP BY 컬럼
HAVING 집계조건         -- 2) 묶은 뒤 집계 필터
ORDER BY ...;

HAVING 실전

카테고리별 아이템 중, 평균 가격이 25000원 이상인 카테고리만.

MySQL · query.sql
SELECT category AS 카테고리,
       COUNT(*) AS 아이템수,
       ROUND(AVG(price)) AS 평균가
FROM item
GROUP BY category
HAVING AVG(price) >= 25000;
카테고리아이템수평균가
무기327567
코스튬244900
⚠️ 왜 WHERE로는 안 되나

WHERE AVG(price) >= 25000은 에러다. WHERE가 실행되는 시점엔 아직 그룹화·평균 계산이 안 됐기 때문이다. 집계 결과를 조건으로 쓰려면 반드시 HAVING.

유저별 결제 — 총액 5만원 이상만

MySQL · query.sql
SELECT user_id AS 유저,
       COUNT(*) AS 결제건수,
       SUM(amount) AS 결제총액
FROM payment
GROUP BY user_id
HAVING SUM(amount) >= 50000
ORDER BY 결제총액 DESC;

WHERE + HAVING 함께

2024-02-01 이후 결제만 모아서(WHERE), 유저별 합계가 3만원 이상인 유저만(HAVING).

MySQL · query.sql
SELECT user_id AS 유저,
       COUNT(*) AS 결제건수,
       SUM(amount) AS 결제총액
FROM payment
WHERE pay_date >= '2024-02-01'
GROUP BY user_id
HAVING SUM(amount) >= 30000
ORDER BY 결제총액 DESC, user_id;

📝 연습문제 — ROLLUP·HAVING

한 문제에서 집계를 여러 개 다루고, 소계·총계(ROLLUP)와 집계 결과 필터링(HAVING)을 함께 훈련한다. WHERE는 묶기 전, HAVING은 묶은 후. ROLLUP을 쓸 때는 ORDER BY를 붙이지 않는다(총계 행 위치가 달라진다). 이 주차에서는 한 테이블만 사용한다.

Q1기초 item을 카테고리별로 묶어 아이템수, 가격합, 평균가(반올림), 최고가를 구하고 맨 아래에 총계 행(ROLLUP)을 붙여라. 총계 행의 카테고리 칸에는 NULL 대신 '총계'를 표시한다(컬럼명 카테고리). ORDER BY는 쓰지 않는다.
💬 힌트: ROLLUP이 만든 총계 행은 GROUP BY 컬럼이 NULL이다 → IFNULL로 이름을 붙인다. 총계 행의 평균·최고는 '전체'에 대한 값이다.

Q10도전 payment를 유저별로 묶어 결제건수, 결제총액, 고액건수(20000원 이상 결제 수), 고액매출(20000원 이상 결제 합)을 구하되 고액 결제가 2건 이상인 유저만 남겨라. 고액매출 높은 순, 같으면 user_id 순.
💬 힌트: SUM(IF(조건, 1, 0))은 '조건에 맞는 행 수'. HAVING에도 집계식을 그대로 쓸 수 있다.

모범답안 보기
answer.sql
SELECT user_id,
       COUNT(*) AS 결제건수,
       SUM(amount) AS 결제총액,
       SUM(IF(amount >= 20000, 1, 0)) AS 고액건수,
       SUM(IF(amount >= 20000, amount, 0)) AS 고액매출
FROM payment
GROUP BY user_id
HAVING SUM(IF(amount >= 20000, 1, 0)) >= 2
ORDER BY 고액매출 DESC, user_id;

Q12도전 user를 서버 + 가입연도로 묶어 유저수, 최고레벨을 구하고 2단 ROLLUP으로 서버별 소계와 전체 총계를 함께 구하라. 총계 행의 서버 칸만 '총계'로 표시하고(컬럼명 서버), 가입연도는 그대로 YEAR(join_date)를 쓴다(컬럼명 가입연도). ORDER BY는 쓰지 않는다.
💬 힌트: 가입연도가 NULL인 행 = 그 서버의 소계, 서버가 '총계'인 행 = 전체 총계. 주의: ROLLUP에서는 YEAR(join_date)를 IFNULL·IF로 한 번 더 감싸면 ONLY_FULL_GROUP_BY 에러(1055)가 난다. 컬럼 그대로(server_id)일 때만 IFNULL로 감쌀 수 있다.

answer.sql
SELECT IFNULL(server_id, '총계') AS 서버,
       YEAR(join_date) AS 가입연도,
       COUNT(*) AS 유저수,
       MAX(level) AS 최고레벨
FROM user
GROUP BY server_id, YEAR(join_date) WITH ROLLUP;
